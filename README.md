# Early Warning System for Loan Default Risk

[![Live Demo](https://img.shields.io/badge/Live_Demo-Render-brightgreen?style=for-the-badge&logo=render)](https://loanrisk-hvof.onrender.com)
🔗 **Live Application:** [https://loanrisk-hvof.onrender.com](https://loanrisk-hvof.onrender.com)

A Java Spring Boot mini project that flags loan customers as **Low / Medium / High risk**

using a transparent, rule-based scoring engine (no black-box AI) — based on their last 3 EMI payments.

## Tech Stack
- Java 17
- Spring Boot 3.2.5 (Web, Data JPA, Thymeleaf)
- H2 in-memory database (zero setup)

## How to Run

**Requirements:** Java 17+ and Maven installed.

1. Unzip the project and open a terminal inside the `loanrisk` folder.
2. Run:
   ```
   mvn spring-boot:run
   ```
3. Open your browser at: **http://localhost:8080**

That's it — no external database setup needed (H2 runs in memory).

## How to Use

1. Log in at `/login`.
2. Click **"+ Add Customer"** and fill in their loan details (including email address).
3. On the dashboard, click **"Log EMI"** next to a customer to record a monthly payment
   (enter the due date, and the paid date — or leave paid date blank if it's unpaid/missed).
4. The dashboard automatically recalculates each customer's **Risk Level** and shows
   a plain-English **reason** for that score.
5. If an EMI is logged as **LATE** or **MISSED**, the system automatically emails the
   customer a reminder — no manual action needed.

## Enabling Email Alerts

By default, email sending will fail silently (logged to console) until you configure it:

1. Use a Gmail account. Turn on 2-Step Verification.
2. Go to Google Account → Security → App Passwords → generate one for "Mail".
3. In `application.properties`, set:
   ```
   spring.mail.username=your-email@gmail.com
   spring.mail.password=your-16-char-app-password
   ```
4. Restart the app. Now, whenever an EMI is LATE/MISSED, the customer gets a real email.

## Enabling Gemini AI (email wording + risk explanations)

The risk **decision** (Low/Medium/High) always stays rule-based — Gemini is only used to
write natural-language text on top of it:
- Personalized wording for the reminder email
- A one-line plain-English explanation of why a customer is flagged, shown on the dashboard

1. Get a free API key at https://aistudio.google.com/app/apikey
2. In `application.properties`, set:
   ```
   gemini.api.key=YOUR_KEY_HERE
   ```
3. Restart the app. If the key is missing/invalid, the app automatically falls back to the
   static email template and just shows the rule-based reason — nothing breaks.

## Risk Scoring Logic (Rule-Based, Explainable)

Looks at the customer's most recent 3 EMI payments:
- 2 or more were **LATE/MISSED** → **HIGH** risk
- Exactly 1 was **LATE/MISSED** → **MEDIUM** risk
- All were **ON_TIME** → **LOW** risk

This logic lives in `RiskScoringService.java` — fully auditable, no hidden ML model.
